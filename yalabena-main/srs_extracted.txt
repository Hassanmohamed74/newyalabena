2. Introduction
2.1 Purpose
This document defines the complete functional and non-functional requirements for a custom Training Management System for Speak Up English Academy. The system is a clone of the Tamkeen TMS feature set, excluding the AI module and excluding all third-party integrations except the three explicitly whitelisted in Section 5. A new monitored Live Chat module is added.
2.2 In-Scope
Full CRM, TMS, LMS, Finance, HR, Certificates, Inventory, Activities, Knowledge Base.
New monitored Student–Teacher Live Chat module.
Integrations limited to: Zoom, OnMeet, EasyKash.
Arabic + English UI with RTL/LTR support.
Multi-branch, multi-role architecture.
AI module (Chatbot,AI grading, Ai Agent).
KPis for system users.
WhatsApp Business / WhatsApp Cloud API integration.
SMS Misr SMS gateways.
Facebook / Meta Ads Lead integration.
EasyKash Integration.
Call Center / IVR integrations.

3. System Overview
3.1 Vision
A single self-hosted platform that replaces all spreadsheets and disjointed tools, covering the full student lifecycle: marketing → lead capture → placement test → enrollment → payment → training → assessment → certificate.
3.2 User Roles
Super Admin (full control)
Branch Manager

3.3 High-Level Architecture (Recommended)
Backend: REST or GraphQL API (Node.js / NestJS or Laravel — implementer’s choice, must be documented).
Frontend: SPA (Next.js / React or Vue).
Database: PostgreSQL (primary). Redis for cache / queues. S3-compatible object storage for files.
Real-time: WebSocket (Socket.IO or similar) for live chat and notifications.
Auth: JWT + refresh tokens; password hashing with Argon2 or bcrypt.
3.4 Localization
Full Arabic (Egyptian) UI with proper RTL.
Full English UI with LTR.
Per-user language preference.
Date formats: dd/mm/yyyy + Hijri optional.
Numerals: Western digits by default; Arabic-Indic optional.

4.7 Live Chat
Note: This is the single most sensitive module. Implementation must follow Section 6 in full.
4.7.1 Core Chat Features
One-to-one chat: Student ↔ Teacher (within an enrolled group only).
Group chat: per-class / per-group room with all students + teacher.
Teacher announcement channel (read-only for students).
Message types: text, emoji, image, file (with size limit).
Read receipts.
Typing indicators.
Online / offline presence.
Message search within a conversation.
Edit own message within 5 minutes (edits visible in audit log).
Delete own message (soft delete — message retained in audit log, replaced by "[deleted]" in UI).
Push / in-app notifications for new messages.
Mute / unmute conversation.
4.7.2 Monitoring &amp; Compliance (MANDATORY)
All messages are logged immutably in an audit table accessible only to Moderator and Super Admin.
Phone-number detection &amp; blocking — see Section 6.1.
Email detection &amp; blocking — see Section 6.2.
Obfuscation detection (Arabic numerals, spelled-out digits, "at"/"dot", spaces between characters, homoglyphs) — see Section 6.3.
Auto-action on detection: block send + show user warning + log attempt to moderator queue.
Moderator dashboard: live feed of flagged messages, ability to suspend a user from chat, ability to view full conversation history.
Strike system: 1st violation → warning, 2nd → 24h chat ban, 3rd → permanent chat ban + escalate to admin.
Image / file scanning: OCR images on upload to detect phone / email in screenshots; scan PDF text content.
Voice notes: blocked by default in v1 (deferred — too complex to monitor without AI; revisit later).
External link policy: links to known social / messenger domains (wa.me, t.me, m.me, instagram.com, facebook.com, telegram.org, signal, viber, etc.) are blocked.
Audit export: moderator can export full chat log of any user / group as PDF or CSV for incident review.

6. Live Chat — Detailed Compliance Specification
Why this section exists: The academy must prevent students and teachers from exchanging private contact info to bypass the platform. Detection must be robust against common evasion tricks.
6.1 Phone-Number Detection
Block / flag any message matching:
Egyptian mobile patterns: 010xxxxxxxx, 011xxxxxxxx, 012xxxxxxxx, 015xxxxxxxx (11 digits).
International format: +20 1x xxxx xxxx, 0020..., 00201...
Any 10–15 consecutive digit sequence.
Digits separated by spaces, dots, dashes, parentheses: 010 1234 5678, 010-1234-5678, (010) 1234.5678.
Arabic-Indic numerals: ٠١٠١٢٣٤٥٦٧٨.
Spelled-out digits in Arabic or English: "صفر واحد صفر…", "zero one zero…", "0 1 0 1 2 3".
Mixed-script (e.g., O1O using letter O instead of digit 0, 1l0 using lowercase L for 1).
WhatsApp-style links: wa.me/..., api.whatsapp.com/send?phone=...
6.2 Email Detection
Standard email regex: [a-z0-9._%+-]+@[a-z0-9.-]+\.[a-z]{2,}.
Obfuscated: name [at] domain [dot] com, name(at)domain(dot)com, name AT domain DOT com.
Arabic obfuscation: "الإيميل بتاعي اسمه عند جيميل نقطة كوم".
Mixed: name@domain dot com, name at domain.com.
Spaces inside emails: n a m e @ g m a i l . c o m.
6.3 Other Contact-Sharing Patterns
Social-media handles: @username followed by mention of Instagram / Telegram / TikTok / Snapchat.
Phrases like "كلمني بره", "ابعتلي على الواتس", "DM me", "text me", "call me at", "my number is", "رقمي هو".
Links to external messengers (block domain list — see 4.7.2).
QR codes in images (OCR + QR decode → if it contains phone / email / URL → block).
6.4 Detection Engine Behavior
Run detection BEFORE the message is persisted and broadcast.
On detection: reject the send, return error to sender’s UI: "Sharing personal contact info is not allowed. This attempt has been logged."
Log every blocked attempt (sender, recipient, full original message, matched rule, timestamp) in chat_violations table.
Send moderator notification for every block.
Configurable severity per rule (block vs warn vs flag-only) — admin-tunable.
6.5 Moderator Tools
Live moderator dashboard with violation feed.
Search violations by user / by date / by rule.
Open full conversation around a violation (with N messages before / after for context).
Apply manual action: warn, mute (timed), ban from chat, escalate to admin.
Whitelist false positives (e.g., a course code that looks like a phone).
Strike counter visible per user.
6.6 Privacy &amp; Legal
Display chat policy notice on first login: chats are monitored, contact-info exchange prohibited.
Consent checkbox required before chat enabled.
Retention policy: chats retained for X months (X to be set by Samir; default 24 months), then archived.
GDPR-style data export on student request (in-app self-service).
7. Non-Functional Requirements
7.1 Performance
Page load (P95) ≤ 2 s on a 10 Mbps connection.
API response (P95) ≤ 500 ms.
Chat message delivery (P95) ≤ 300 ms within same datacenter.
Support 500 concurrent users in v1; architecture must scale to 5,000.
7.2 Security
HTTPS-only (HSTS).
Argon2 / bcrypt password hashing.
JWT short-lived access token + refresh token.
Rate limiting on login, password reset, public forms.
OWASP Top 10 hardening (parameterized queries, output encoding, CSRF on state-changing routes, etc.).
Audit log for all sensitive actions.
File upload validation (size, MIME, extension, antivirus optional).
Two-factor auth for Super Admin and Finance roles.
Backups: daily DB + weekly full; 30-day retention minimum.
Secrets via environment variables, not in code.
7.3 Privacy
Student PII encrypted at rest (column-level for sensitive fields).
Role-based access — sales agent cannot see another branch’s students.
Data export &amp; deletion request flow.
7.4 Usability
Consistent design system across all modules.
Empty states with helpful guidance.
Accessible: keyboard navigation, ARIA labels, sufficient color contrast.
Inline validation on forms.
Loading skeletons, no full-page reloads.
7.5 Reliability
Uptime target: 99.5% monthly.
Graceful degradation if Zoom / OnMeet / EasyKash is down (queue + retry).
Daily automated DB backup with successful-restore test monthly.
7.6 Localization
All UI strings in i18n files (ar.json, en.json) — no hard-coded strings.
RTL / LTR layout switching.
Date / time / currency localized.
7.7 Browser Support
Latest 2 versions of Chrome, Edge, Firefox, Safari.
Mobile Safari + Chrome on iOS / Android.
